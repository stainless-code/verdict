**Security:** every review launch now also runs in the host's OS sandbox (STA-538). `verdict run --agent` finders, cross-checks, repair rounds and drain, and `verdict loop`'s review step, run under `sandbox-exec` with a generated profile on macOS and under `bwrap` on Linux, with the network open so the agent reaches its model API. A review agent can write only its launch's snapshot directory (its working copy and private `TMPDIR`), its own cited data paths (`claude`: its session, log and cache directories under `~/.claude`, the macOS login keychain and cache; `codex`: its sessions, logs, sqlite stores and token file under `~/.codex`; `opencode`: its XDG data and state directories; `pi`: `~/.pi/agent/sessions` and `auth.json`; each relocation variable honored), and the devices a process needs — never its own config or code (`~/.claude.json`, claude's settings, hooks and plugins, `~/.config/opencode` and opencode's installed packages, pi's settings and extensions), no other dotfile in `HOME`, nothing else under `~/.config`, never your checkout, the execution's shared snapshot, or another launch's snapshot directory (which macOS also hides from its reads) — and cannot read the credential table `verify --sandbox` hides, which now also covers glab's `~/.config/glab-cli` and `GLAB_CONFIG_DIR` (for `verify --sandbox` too). Before, an agent tool that took an absolute path could write anywhere you can and read your credentials into review text. `codex` keeps its own `--sandbox workspace-write` sandbox instead, because a nested Seatbelt profile fails on macOS; it confines its writes, but its reads are not confined, and `run` warns so. With no sandbox (Windows, Linux without bubblewrap, a probe that fails), `claude` and `codex` still run with a warning that their reads are not confined, and every other agent refuses the new `review-sandbox-unavailable` code before it starts; `--allow-unsandboxed-review` on `run` and `loop` runs every review launch without the sandbox, warned: without it only `claude` and `codex` are kept in their copy by their own tools, and the opt-out accepts that any other agent can write outside its copy (a sibling launch's copy, your checkout, your files) and read your credentials. A row with no state paths can write only its snapshot and `TMPDIR`, and `run` warns so; an agent you define in prefs declares its own writable data paths as `agents.<name>.state_locations`. `run --json` reports the posture in `data.sandbox` (`--print` adds the wrapper argv with a `{snapshot}` placeholder), and `loop --print` carries it on each review step in `plan[].sandbox`. A sandboxed launch runs the agent binary verdict resolved by its absolute path. The loop's fix spawn is never sandboxed: editing your checkout is its job. The sandbox also closes every unix socket (an ssh agent, docker, systemd, tmux; on macOS the resolver's and syslog's stay open), hides the host temp roots (and `/run` on Linux), strips `SSH_AUTH_SOCK`, `DBUS_SESSION_BUS_ADDRESS`, `GPG_AGENT_INFO`, `TMUX`, `NVIM`, `XDG_RUNTIME_DIR`, `DISPLAY`, `WAYLAND_DISPLAY` and `XAUTHORITY`, and on macOS denies every Mach service lookup but an allowlist (directory lookups, trustd, SystemConfiguration, and the keychain brokers only for claude, whose login they hold) — so no preference write, pasteboard, LaunchServices registration, login item, window server or Shortcuts; a TLS client that loads its roots from the keychain gets `SSL_CERT_FILE=/etc/ssl/cert.pem` unless you set one. On Linux `/var/tmp` is hidden too; the network namespace stays the host's, so abstract-namespace unix sockets (a `dbus-launch` session bus) and sockets under `HOME` outside the credential table stay reachable. Each writable data directory is pinned so it cannot be swapped for a link, a state path that is or passes through a link refuses, and the state is re-checked before every launch. claude's shell snapshots, session env and (on macOS every, on Linux every existing) project memory, codex's shell snapshots, and opencode's managed tools and packages are read-only; opencode's data directory is writable whole (its database journals and the directories it makes at startup) with that code read-only inside it; every read-only path is denied writes explicitly. The credential table now also hides the agent logins (`~/.codex/auth.json`, opencode's and pi's `auth.json`, `~/.claude/.credentials.json`, `~/.config/github-copilot`, `~/.gemini/oauth_creds.json`, `~/.config/git/credentials`, opencode's `mcp-auth.json`), the X11 cookie and the 1Password, Bitwarden and Secretive ssh-agent socket directories, each agent keeping its own, for `verify --sandbox` too. A relocation root that is a link, and a state path inside a credential directory, refuse. A policy that cannot be built refuses `review-sandbox-unavailable` instead of falling back unsandboxed; claude review launches pin `--permission-mode default`, and any write-tool allow rule in your own Claude settings voids claude's no-sandbox fallback; codex's `-s<mode>`, `-c`/`--config`, `-p`/`--profile`, `--enable`/`--disable`, `--remote`, `--trust` and `-o` count as deciding its sandbox, codex's own sandbox gets `-c sandbox_workspace_write.writable_roots=[]`, and a codex wrapped in verdict's macOS sandbox is told to pass `--sandbox danger-full-access`. pi review launches carry `--no-approve`, so the reviewed tree's project-local pi files never load. `backtest` replays are now sandboxed like every other review: every commander verdict runs is, unless a test double says it simulates its processes. Review launches point claude's own scratch directory (`CLAUDE_CODE_TMPDIR`) at their private `TMPDIR`.

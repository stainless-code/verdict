**Security:** every review launch now also runs in the host's OS sandbox (STA-538). `verdict run --agent` finders, cross-checks, repair rounds and drain, and `verdict loop`'s review step, run under `sandbox-exec` with a generated profile on macOS and under `bwrap` on Linux, with the network open so the agent reaches its model API. A review agent can write only its launch's snapshot directory (its working copy and private `TMPDIR`), its own cited data paths (`claude`: its session, log and cache directories under `~/.claude`, the macOS login keychain and cache; `codex`: its sessions, logs, sqlite stores and token file under `~/.codex`; `opencode`: its XDG data and state directories; `pi`: `~/.pi/agent/sessions` and `auth.json`; each relocation variable honored), and the devices a process needs — never its own config or code (`~/.claude.json`, claude's settings, hooks and plugins, `~/.config/opencode` and opencode's installed packages, pi's settings and extensions), no other dotfile in `HOME`, nothing else under `~/.config`, never your checkout, the execution's shared snapshot, or another launch's snapshot directory (which macOS also hides from its reads) — and cannot read the credential table `verify --sandbox` hides, which now also covers glab's `~/.config/glab-cli` and `GLAB_CONFIG_DIR` (for `verify --sandbox` too). Before, an agent tool that took an absolute path could write anywhere you can and read your credentials into review text. `codex` keeps its own `--sandbox workspace-write` sandbox instead, because a nested Seatbelt profile fails on macOS; it confines its writes, but its reads are not confined, and `run` warns so. With no sandbox (Windows, Linux without bubblewrap, a probe that fails), `claude` and `codex` still run with a warning that their reads are not confined, and every other agent refuses the new `review-sandbox-unavailable` code before it starts; `--allow-unsandboxed-review` on `run` and `loop` runs every review launch without the sandbox, warned. A row with no state paths can write only its snapshot and `TMPDIR`, and `run` warns so; an agent you define in prefs declares its own writable data paths as `agents.<name>.state_locations`. `run --json` reports the posture in `data.sandbox` (`--print` adds the wrapper argv with a `{snapshot}` placeholder), and `loop --print` carries it on each review step in `plan[].sandbox`. A sandboxed launch runs the agent binary verdict resolved by its absolute path. The loop's fix spawn is never sandboxed: editing your checkout is its job.

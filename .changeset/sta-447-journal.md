Verdict now writes an append-only per-bundle invocation journal under `<state>/verdict/journal/<repo-key>/<pr>.jsonl` (`$XDG_STATE_HOME`, falling back to `~/.local/state` on Unix or `%LOCALAPPDATA%` on Windows) for every bundle-writing CLI and MCP call, and adds the read-only `verdict journal <owner/repo> <pr|local-name> [--json]` verb (plus its MCP tool, Go facade method, TypeScript client method, shell completion, and `schemas/journal.schema.json`). Each call records paired `start` and `end` lines carrying the canonical `repo` root, redacted `argv`, content-digest `bundle.before`/`bundle.after` tamper-evidence hashes, exact `wrote`/`removed` paths with SHA-256 digests, exit code, refusal code, warnings count, and `next` hint, bounded at 1 MiB with atomic whole-line truncation and non-fatal append warnings. The folded `verdict journal` summary pairs each call under a unique `step` key, reports the size-cap notice under `truncation`, and publishes `bundle.unobserved` with no file diff when a content sweep fails instead of claiming every file changed. Because the journal lives outside the repository and `.verdict/`, dry runs, refusals, and bundle receipts stay completely untouched.

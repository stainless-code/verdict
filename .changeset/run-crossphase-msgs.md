Two-finder `run` now repairs a cross check instead of failing it blind: the cross directive names the accepted quote sides (`RIGHT` for the new side of the diff, `LEFT` for a deleted line), and one repair round carries every problem the checker found — the row set, each row's fields, and each quote against the diff, with JSONPath, code, and fix — so an agent that wrote `side: "new"` fixes it on the next round. A cross quote's `side` is now required and refused when absent or empty by the cross check and by every reader of `verification/verdicts.json`; pre-1.0, a receipt that relied on the old empty-side default no longer verifies, so re-run the execution. An execution left incomplete names each failed phase and, when `--resume` can continue it, that recovery. `gate` over an execution that stopped short fails in every mode, reads `findings` as `unknown` instead of "no open findings", and names `run --resume`, then `record`. A `review-insufficient` refusal that lists no evidence problems no longer points at gaps "named above", and the SDK's `RefusalError` now carries `Problems`. An execution that stopped short in a way `--resume` refuses reads `unknown` as well, and its recovery is a fresh `run`, naming the gap. `run`'s `re-enter:` line quotes every operand, keeps the flag names after `--` but redacts every value (model and budget values included), scrubs credentials, adds a shell comment asking for redacted values back, carries `--resume` before `--` when the refusal says to resume, and drops it after `resume-drift` or `cannot-resume`.

**Security:** every review launch now runs in a disposable snapshot of the reviewed tree, never in your checkout (STA-537). `verdict run --agent` finders, cross-checks, repair rounds and drain, and `verdict loop`'s review step, each start in their own copy of the content-bound snapshot `verify` takes, with a copy of the bundle at its usual `.verdict/state/<bundle>/` path. When the agent exits, verdict copies back only the artifacts that launch is expected to write (`review.json` and, beside a bundle-level review, `cost.json`, `chunks/chunk-*.cost.json`, `validation.json`, `verification.json`; a finder's or cross-check's own artifact; `drain.replies.json`), each a lone regular file of at most 32 MiB, written atomically with the agent's own timestamp. Anything else the agent wrote, inside or outside the bundle copy, is discarded and named in a warning. Before, every agent but claude kept its edit tools in your checkout, so a prompt-injected diff could plant code there. Review agents still read the reviewed tree and use the network; they are not OS-sandboxed, so a tool that accepts an absolute path can still reach other paths. `claude` review launches add `--setting-sources=user`, so the reviewed tree's own `.claude/settings*.json` (hooks, allow rules) never loads; `--setting-sources` after `--` now refuses `bad-flags` unless `--allow-shell` is set. `codex` review launches add `--sandbox workspace-write`, scoped to the snapshot, so codex writes `review.json` itself instead of relying on stdout salvage (`--print` renders the command without it, and your own `--sandbox` after `--` drops it). The loop's fix phase still edits your checkout. A snapshot that cannot be made refuses `agent-spawn-failed` before any agent starts.

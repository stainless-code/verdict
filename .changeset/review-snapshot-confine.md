**Security:** every review launch now runs in a disposable snapshot of the reviewed tree, never in your checkout (STA-537). `verdict run --agent` finders, cross-checks, repair rounds and drain, and `verdict loop`'s review step, each start in their own copy of the content-bound snapshot `verify` takes, with a copy of the bundle at its usual `.verdict/state/<bundle>/` path. When the agent exits, verdict copies back only the artifacts that launch is expected to write (`review.json` and, beside a bundle-level review, `cost.json`, `chunks/chunk-*.cost.json`, `validation.json`, `verification.json`; a finder's or cross-check's own artifact; `drain.replies.json`), each a lone regular file of at most 32 MiB, written atomically with the agent's own timestamp. Anything else the agent wrote, inside or outside the bundle copy, is discarded and named in a warning. The copy holds nothing that leads back to your repository: the snapshot drops its worktree pointer and registration as soon as it is made, each copy's `.git` is an empty repository of its own, and no symlink, `.git`, or `.verdict/state` of the tree's (in any case) is copied. Outside a git checkout the copy holds the bundle alone. Each launch gets a private `TMPDIR`; the agent's environment drops the variables that name your directories (`OLDPWD`, `INIT_CWD`, `GIT_DIR` and git's other location and `GIT_CONFIG_*` variables, and the like). A checkout inside the temp directory keeps its snapshots under the user cache directory instead (`XDG_CACHE_HOME`), refusing without one. Copy-back pins both directories and reads each artifact as the very file the walk saw — never through a link, never waiting on a FIFO, refusing a hard link — and a chunk's cost record comes back only for a chunk the manifest lists (1 MiB cap). Review agents still read the reviewed tree and use the network; they are not OS-sandboxed, so a tool that accepts an absolute path can still reach other paths. Every `claude` review launch, `--allow-shell` or not, adds `--setting-sources=user` and `--strict-mcp-config`, so the reviewed tree's own `.claude/settings*.json` (hooks, allow rules) and `.mcp.json` never load; after `--`, claude's `--settings`/`--setting-sources`/`--plugin-dir`/`--mcp-config`/`--strict-mcp-config` and codex's `-C`/`--cd`/`--worktree`/`--approve-for-me`/`--dangerously-bypass-hook-trust` now refuse `bad-flags` on a review launch unless `--allow-shell` is set. `codex` review launches add `--sandbox workspace-write -c sandbox_workspace_write.exclude_slash_tmp=true`, scoped to the snapshot, so codex writes `review.json` itself instead of relying on stdout salvage (`--print` renders the command without it, and your own `--sandbox` after `--` drops it). The loop's fix phase still edits your checkout. A snapshot that cannot be made refuses `agent-spawn-failed` before any agent starts.

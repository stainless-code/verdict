Sandboxed `opencode` reviews now sign in with your real opencode login. Current opencode keeps its logins in its database rather than `auth.json`, so verdict reads the database's credential table read-only, without SQLite, and seeds each provider's login into the launch's throwaway data home. `OPENCODE_DB` now points at that throwaway copy. The review sandbox now hides opencode's whole data directory (`~/.local/share/opencode`, `$XDG_DATA_HOME/opencode`, and the directory `OPENCODE_DB` points into) from every agent, because its database holds the same tokens as `auth.json`. A database or journal file created there mid-review is hidden too. `agy` now declares `~/.gemini` as read-only state. On macOS, a sandboxed `agy` review warns before launch that its keychain sign-in stays closed and that `GEMINI_API_KEY` signs it in instead. The keychain stays closed because agy keeps a shell, and with the keychain open that shell could read every token stored there, `gh`'s included. Under `--allow-shell`, claude's keychain stays closed for the same reason; a macOS `claude` review then warns to set `ANTHROPIC_API_KEY`.

Sandboxed `opencode` reviews now sign in with your real opencode login. Current opencode keeps its logins in its database rather than `auth.json`, so verdict reads the database's credential table read-only, without SQLite, and seeds each provider's login into the launch's throwaway data home. `OPENCODE_DB` now points at that throwaway copy. The review sandbox now hides opencode's whole data directory (`~/.local/share/opencode`, `$XDG_DATA_HOME/opencode`, and the directory `OPENCODE_DB` points into, and its target's when it is a link) from every agent, because its database holds the same tokens as `auth.json`. A database or journal file created there mid-review is hidden too. `agy` now declares `~/.gemini` as read-only state. On macOS, a sandboxed `agy` review warns before launch that its keychain sign-in stays closed, and that it signs in only with `GEMINI_API_KEY` set and agy configured to use it. The keychain stays closed because agy keeps a shell, and with the keychain open that shell could read every token stored there, `gh`'s included. Under `--allow-shell`, claude's keychain stays closed for the same reason; a macOS `claude` review then warns to set `ANTHROPIC_API_KEY`.

Credential paths now preserve operator values until the sandbox follows each link, so `..` after a link names the same target the operating system opens. This covers relocated stores and home-relative entries too, including dangling links whose targets appear after launch on macOS. A link with an empty target, or `..` after a missing path component, refuses the review with a policy error, including for claude and codex.

`verdict run --resume` continues the two-finder execution the bundle's `launcher.json` records instead of starting a new one. Before anything launches or is written, it verifies a recorded fingerprint over `full.diff`, `run.json` and the controls it seals, `context.txt`, the bundle's `prompts_hash` and this binary's, the reviewed head, the agent, its definition source, and a digest of its resolved launch definition, the finder topology, and the resolved finder source and review depth, then it verifies the bound finder and cross artifacts and the cross rows against the batch it would ask about. It reuses every phase whose sealed artifact still passes its checks and re-runs only the incomplete ones. Any drifted input, damaged artifact, symlinked phase path, or unaffordable launch refuses with `resume-drift` or the spend code and leaves the interrupted record — its bound artifacts and unresolved failures — exactly as it was, so a retried `--resume` reads the same bundle and never reuses bytes no attempt sealed. A resume that reuses every phase of a finished execution launches nothing, so it asks no spend guard. Control and config drift still hits the existing `controls-stale` gate first, a bundle with nothing to continue refuses `cannot-resume`, and no refusal launches an agent. Each barrier publishes the artifacts it bound, so an interrupted attempt is itself resumable. `launcher.json` binds bundle paths portably, so a Windows bundle resolves the same artifact keys a Unix one does. `data.resume` and the manifest's `resume` block name the reused and executed phases.

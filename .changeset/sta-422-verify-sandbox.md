`verify --sandbox` on macOS is now a real boundary, not the network half alone. The generated Seatbelt profile still denies the network, and now also denies the keychain broker (`com.apple.SecurityServer`), so `security find-generic-password -w` returns nothing. It denies every write outside the reviewed root, the per-run private `TMPDIR`, and `/dev/null`/`/dev/tty`/`/dev/fd/*`, so a command can no longer plant a LaunchAgent or a shell rc file that runs unsandboxed later. It also denies reads and writes of the credential paths and of the shared host temp roots. Each run gets a private `0700` `TMPDIR`/`TMP`/`TEMP`/`GOTMPDIR`, with `GOCACHE` and `XDG_CACHE_HOME` inside it, so `go build` and `go test` keep working. A cache elsewhere under `HOME` (npm, pip, cargo) now fails to write; point it at `$TMPDIR` from the command. A private directory that cannot be removed now surfaces as a `sandbox cleanup:` warning. Seatbelt is a policy, not a mount namespace: the rest of the host filesystem stays readable.

One credential table now serves Linux and macOS. It is applied under the child `HOME`, the `verdict` process `HOME`, and the passwd-database account home. It adds `~/.terraform.d`, `~/.cargo/credentials.toml`, `~/.cargo/credentials`, `~/.vault-token`, and `~/Library/Keychains`. It also covers the stores these variables move, read from both environments: `XDG_CONFIG_HOME/gh`, `GH_CONFIG_DIR`, `AWS_SHARED_CREDENTIALS_FILE`, `AWS_CONFIG_FILE`, `DOCKER_CONFIG`, each `KUBECONFIG` entry, and `CLOUDSDK_CONFIG`. A reviewed root inside a credential path refuses `sandbox-unavailable`.

Linux hosts without bubblewrap can opt into `verify --sandbox-network-only` (CLI, MCP `sandboxNetworkOnly`, Go `VerifyRequest.SandboxNetworkOnly`). It probes and runs `unshare --user --map-root-user --net`, which isolates the network only. The host filesystem, the host `/proc`, and filesystem unix sockets such as `docker.sock` and the ssh-agent socket stay reachable, and every run warns so. Such a run records `sandboxMechanism: "unshare-net"` and never `sandboxed`. `--sandbox` still refuses `sandbox-unavailable` rather than downgrade, the new flag refuses on non-Linux hosts, and passing both refuses `bad-flags`.

`--sandbox` also protects the reviewed repository's git control files on both platforms, because git runs those later outside any sandbox. Writes are denied to `<root>/.git`, the git directory a `.git` file names, and a linked worktree's common directory: `--ro-bind` on Linux, Seatbelt denies on macOS. On macOS, creating any `.git` path below the root (a nested repository, a `.git` file, or a symlink) is denied too. `git status` and `git diff` keep working; `git commit`, `git stash`, and other writes to the repository now fail inside the sandbox.

`sandboxed: true` now means the full shape (`bwrap` or `sandbox-exec`) and nothing weaker. `sandboxMechanism` names the wrapper in `patch.json`, in `--json` data, and in the Go `VerifyResponse.SandboxMechanism`. The deep-group receipt records it as `sandbox_mechanism`.

_Compatibility:_ the receipt keeps `schema_version` `"1"` because the key is optional and additive, as `sandboxed` was in 0.7.0. Older releases decode receipts strictly, so they refuse a receipt that carries `sandbox_mechanism` as unreadable. Re-run `verify --group … --command …` with the binary that will read the receipt.

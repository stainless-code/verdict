`verdict report <repo> <pr|slug> --compare <baseline>` groups the same stable finding signatures against a prior bundle (a directory, or a PR/`local-<name>` resolved in the same `.verdict/state`) into four buckets: `new`, `persisting`, `resolved`, and `not reviewed`. Persisting rows name severity and status moves; resolved rows are proven only by attested coverage of the finding's hunk (`covered-and-absent`) or by a provider PR's full diff no longer touching its file or hunk (`removed-from-diff`); an incremental `--since` delta, an excluded file, an unattested hunk, a path-filtered local bundle, and a missing snapshot all read `not reviewed` with their own reason, so an absent finding can never read as a false fix. A baseline that is missing, symlinked, corrupt, unrecorded, the reported bundle itself, or from another repository refuses typed (`missing-compare-bundle`, `unsafe-compare-bundle`, `corrupt-compare-bundle`, `unrecorded-compare-bundle`, `bad-compare`). `--json` adds `data.compare` with the baseline metadata, the four counts, and four deterministically sorted arrays; the Go SDK (`ReportRequest.Compare`), the MCP `report` tool, and the TypeScript client schema carry the same flag, and the comparison stays advisory — it composes no gate and changes no exit code.

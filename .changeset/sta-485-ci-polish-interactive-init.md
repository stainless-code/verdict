`verdict init --ci github` gains an opt-in `/verdict` pull-request comment re-run with `--comment-trigger`: the generated workflow adds `issue_comment: types: [created]`, and the job runs only for a comment on a pull request written by an `OWNER`, `MEMBER`, or `COLLABORATOR` whose body is exactly `/verdict` or starts with `/verdict `. The concurrency key is conditional for the same reason the gate is: GitHub applies a `concurrency` group before any job-level `if:` runs, so every other comment lands in `verdict-noop-<run_id>` and cancels nothing, while `/verdict` joins that pull request's `verdict-<number>` group and supersedes the review in flight. The trigger never adds `pull_request_target` and never checks out a pull request head — an `issue_comment` event checks out this repository's default branch — and the comment body is read only in expressions, never interpolated into a script. Naming the flag with any provider but `github` is a usage error that writes nothing, and a workflow generated without it keeps its exact bytes.

Bare `verdict init` is now a guided run on a terminal: three questions (preset, workflow defaulted from the `origin` remote's host, and agent defaulted to the first installed agent CLI on `PATH`), Enter keeps each default, and the run writes byte-identical files to the explicit invocation that spells the same answers. Any selection flag, `--json`, or a redirected stdin or stdout keeps the current non-interactive behavior untouched, and Ctrl-D aborts before anything is written. `--ci`/`--agent`/`--key-secret`/`--print`/`--comment-trigger` reach the Go facade's `InitRequest` too, while the MCP `init` tool keeps writing controls only and names the new field in its omit list so the published schema cannot drift.

`verdict demo [<public-github-pr-url>] [--agent <name>] [--keep] [--json]` is a new verb: one review with no setup and no risk. A public pull request URL is read with `gh` when it is signed in for github.com and over the anonymous public REST API otherwise; with no argument the verb reviews your own working tree inside a git repository. The first runnable coding-agent CLI on `PATH` is detected (a documented preference order that skips rows with a launch warning or a shared binary name), overridable with `--agent`, and refused `agent-missing` with a two-line install guide when none is installed. The launch uses one finder, and the recorded review prints byte-identically to the body `post` publishes, with the change topology shown even below the size gate where a publication would omit it.

Every artifact lands in one disposable `verdict-demo-*` temp directory, removed on exit unless `--keep`, so nothing is written in the caller's repository and no `.verdict/journal` entry is made there. Posting is unreachable by construction: the demo packages never import or name `internal/core/post`, posting is never called, and the offline eval proves every host call was a read. Public reads reuse the shared provider tail (`PR.json`, `full.diff`, `filesource.json`, truncated thread feed), and an adapter-only `NoRepoLayer` posture reads the absent repository control and configuration layers as absent, so a URL run works outside any checkout while normal `fetch` still refuses an unreadable base. `record` now exposes the curated body it already computed (`Response.Body`, never wire data, no schema change), which is what the demo renders.

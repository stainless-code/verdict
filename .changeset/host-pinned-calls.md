Every `gh` and `glab` call now names the target's host itself, so `GH_HOST`, `GITLAB_HOST`, or the CLI's default host can no longer send a fetch, a thread reply, or a review to another host's pull request with the same `owner/repo` and number. A target from a URL or the `origin` remote carries its host, and the calls name it: `gh api --hostname <host>`, `gh pr … --repo <host>/<owner>/<repo>`, `glab api --hostname <host>`, `glab mr … -R https://<host>/<path>`. `post` always posts to the host its bundle was fetched from. The new typed refusal `host-mismatch` (exit 1) names both hosts when no call can be pinned: a Forgejo target on another host than `FORGEJO_HOST`, a GitLab target on a non-default port (glab's `--hostname` takes none), or a bundle fetched from another host than the target. Host equality now compares the authority, so two hosts that differ only by a non-default port are different hosts. Migration: if `post` refuses with `host-mismatch`, re-fetch the target or pass a target on the bundle's host. A typed `<owner/repo> <pr>` names no host and still follows the host CLI's own default. See `docs/manual.md` § Targets.

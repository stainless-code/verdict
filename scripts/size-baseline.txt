# Ceilings for the release binary and the module graph: `make size`
# (scripts/size.sh) fails when a shipped target or the dependency count grows
# past its line, when a target has no line, or when a line names a target the
# release contract no longer ships.
#
# A deliberate growth raises the line in the same change, so the cost shows in
# the diff next to the code that caused it. Measured off a GoReleaser-identical
# build (see the script's flags), sized for the small drift a patch-level
# toolchain bump can cause. Format: `<goos>/<goarch> <bytes>`, one `deps <n>`.
# Review-input checker + dry run: CheckReview, its problem envelope, and the
# dry-run data profile added ~60 KiB across every target. Complete checker
# coverage plus the human problem list added ~20-40 KiB more. Review-input
# normalization (NormalizeReview, repair merge, repairs profile, Basis
# rewrite, rigor_source) adds ~30-50 KiB more.
# Finding categories + repair: taxonomy, counts/filters, core bad-category
# refusal, anchor+rigor gate eligibility, false-category warning, and the
# category wire fields added ~30-65 KiB per target (amd64 over budget).
# Patch identity on top: bundle identity binding, Verify recompute, receipt
# strictness, and raw-read distinction add ~35-45 KiB per target over the
# category baseline. Ceilings sit at the next 10 KiB above the combined
# measurement. Final receipt-number validation and shared raw-entry checks
# add up to another 9 KiB; only overflowing ceilings are refreshed.
# Typed configuration adds strict parsing, captured provenance, scoped plans,
# grouped cost/cap enforcement, and validation receipts. Same-toolchain release
# builds grow by about 0.55-0.66 MB per target; dependencies remain zero. These
# intentional feature costs are rounded to the next 10 kB as above.
# Preview and local-rename enforcement on top: the prospective-requirements
# view, captured-cost identity, old-path policy joins, and both-endpoint
# privacy filtering. Same-toolchain release builds grow a further 5.7-10.7 kB
# per target, so the five ceilings that overflowed move to the next 10 kB above
# their exact measurement; linux/arm64 keeps its higher existing ceiling.
# Preview repair on top: verified captured rename identities in the preview
# view, plus the explicitly untrusted source-snapshot policy head. Only
# darwin/amd64 overflowed, by 2048 bytes, so its ceiling moves to the next
# 10 kB above the exact measurement; every other ceiling stays put.
# The review-fix pass (scope-audit exemption, learn-store seeding, root-resolved
# kb reads, the doctor and front-door fallbacks, phase-two spend resolution, the
# compliance gate dimension, and its per-dimension action table) added 66 bytes
# over darwin/arm64's ceiling and stayed inside every other one; that ceiling
# moves to the next 10 kB above the exact measurement.
# One-warning-per-gap and the depth-scoped state negation add 512 bytes to
# windows/amd64, the only ceiling they cross; it moves to the next 10 kB above
# the exact measurement and the others stay put.
# Version-scoped lens certification on top: the per-version record-key table,
# the refusal sentences that name a field or a version, and the tolerant
# aggregator path. Measured deltas track segment padding more than code volume
# (darwin/amd64 and linux/amd64 each gained exactly 8192 bytes, windows/amd64
# 5632, windows/arm64 4608, while darwin/arm64 did not move), and linux/arm64,
# whose segments pad to 64 KiB, crossed a boundary for 65536. The three
# ceilings that overflow move to the next 10 kB above their exact measurement;
# darwin/arm64 and windows/amd64 stay put. windows/arm64 then measured 10919936
# locally but 10920960 on CI, 960 over its ceiling, so it moves to the next
# 10 kB above the CI measurement.
# Cost naming on top: the shared record predicate, the seat check, the
# plan-everything-before-writing pass, and the refusal sentences that name a
# file and an entry. Measured on the stacked tree (darwin/amd64 12041056,
# darwin/arm64 11053250, linux/amd64 11833504, windows/amd64 12159488,
# windows/arm64 10940928); each ceiling that crosses moves to the next 10 kB
# above its own measurement, and linux/arm64 stays put.
# The review-response round on that same change (plan-before-merge, mtime
# preservation, the scoped-panel and cap refusals, and a per-chunk read path)
# adds 752-7616 bytes: four ceilings cross and move to the next 10 kB above
# their exact measurement — darwin/amd64 12057616, linux/amd64 11841696,
# windows/amd64 12170752, windows/arm64 10950656. darwin/arm64 (11053426) and
# linux/arm64 (10879136) stay inside and keep their ceilings.
# The bot-fact-check round adds the rollup's top-record drop, the bindable
# guard, and the plan stamp the write compares against: 2832-12288 bytes.
# Measured here: darwin/amd64 12065936, darwin/arm64 11070066, linux/amd64
# 11849888, linux/arm64 10879136, windows/amd64 12180992, windows/arm64
# 10959360 (the earlier 10950656 note was stale). Three ceilings cross and
# move to the next 10 kB above their measurement; the other three stay put.
# Truthful public surfaces adds the SDK flag plumbing and one refusal hint.

# Unsafe blocks without a stated invariant

`unsafe` is a promise the compiler cannot check. The block is reviewable only
when it states, next to the block, which invariant makes it sound and why the
surrounding code maintains it.

## When to flag

- An `unsafe { ... }` block with no `// SAFETY:` comment stating the
  invariant, or a comment that restates the operation instead of the proof
  ("SAFETY: this is unsafe").
- Raw-pointer dereference without establishing non-null, alignment,
  initialization, provenance, and lifetime.
- `std::mem::transmute` without proving size, alignment, and bit-validity of
  the destination type.
- `str::from_utf8_unchecked`/`String::from_utf8_unchecked` on bytes not
  proven UTF-8; `slice::from_raw_parts` on a length not proven in-bounds;
  `Vec::set_len` on elements not proven initialized.
- `get_unchecked`/`get_unchecked_mut` with an index not proven in-bounds, or
  `unsafe` FFI calls whose null/ownership/threading contract is not checked.
- A `static mut` access with no synchronization argument.

## Do NOT flag

- A block carrying a `// SAFETY:` comment that does state the invariant and
  the reason it holds at that call site. Do not demand a fixed length or a
  particular wording.
- Unsafe code generated by a binding generator or a macro the diff only
  consumes (a `bindgen` output, `include!` of generated bindings); report the
  hand-written wrapper instead.
- An `unsafe fn` whose `# Safety` documentation states the caller contract,
  where the unsafe operations inside are covered by that contract.
- `unsafe` used only to call a well-audited crate API whose own documented
  contract the comment cites, when the comment shows why the local values
  satisfy it.
- A safe wrapper whose invariant is enforced by construction (a newtype that
  validates on creation and never exposes a mutable path).

## Evidence

Quote the block and the comment (or its absence). Name the specific
invariant a caller can violate and the undefined behavior that follows.

# Wildcard access grants

An IAM statement with `Action = "*"` or `Resource = "*"` lets a compromised
principal reach every API or every object. A public bucket ACL or a trust
policy with `Principal = "*"` exposes the account to anyone.

## When to flag

- `Action = "*"` in an allow statement, especially when paired with
  `Resource = "*"`; the pair is administrator access.
- `Resource = "*"` on an allow statement whose actions can mutate or read
  sensitive data (`s3:*`, `iam:*`, `kms:*`, `secretsmanager:*`, `s3:GetObject`
  over every bucket).
- `NotAction`/`NotResource` used with an allow statement: the effect is
  everything except the listed items, which is usually wider than intended.
- `Principal = "*"` in a role trust policy or resource policy with no
  `Condition` (an external ID, `aws:SourceAccount`, `aws:SourceArn`, or an
  organization check).
- A public S3 ACL (`acl = "public-read"`/`"public-read-write"`) or a bucket
  policy with `Principal: "*"` on object access.
- An `aws_iam_policy`/`aws_iam_role_policy` attachment that grants broader
  permissions than the workload's callers use, when the diff widens an
  existing statement.

## Do NOT flag

- `Resource = "*"` on actions whose API requires it and that are read-only
  metadata calls (`ec2:Describe*`, `cloudwatch:List*`), where the diff shows
  the intent.
- A resource ARN scoped to one bucket/table/queue, even when the action is a
  wildcard (`s3:GetObject` on `arn:aws:s3:::my-bucket/*`).
- `Principal = "*"` in a trust policy guarded by a `Condition` that pins the
  account, organization, external ID, or source ARN.
- AWS service-linked roles and policies the provider manages, or a policy
  whose wildcard is generated by the provider and not authored in the diff.
- A public website bucket whose objects are explicitly intended to be public,
  where the diff also shows the public access block configuration that keeps
  the rest private.
- `Resource = "*"` in a deny statement (denies are broad by design) or in a
  permissions boundary.

## Evidence

Quote the statement and the principal/resource. Name the action and data an
attacker gains, and why the grant is wider than the workload needs.

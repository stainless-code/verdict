- **Reviews that show their evidence.** An agent now hands in findings only, each quoting the line it is about, and verdict checks every quote against the diff. A clean review must quote each changed hunk it read, and verdict, not the agent, decides approval, so a review that checked nothing can no longer approve.
- **Two reviewers by default.** `run --agent` launches two independent finders, and each one cross-checks the other's findings before they count. Pass `--finders 1` for the old single pass, or `--budget auto` to pick the depth from the diff.
- **Verify runs on a clean copy, and its proof names what it ran.** `verdict verify` runs your command in a throwaway snapshot of your checkout, and the receipt records the exact content it ran on, so a fix counts as addressed only when it passed on the content being graded. Windows checkouts with `core.autocrlf` name the same content as the commit, and listing `node_modules` or `.venv` in `verify.share` reuses them instead of reinstalling.
- **`verdict loop`: let an agent review and fix its own work.** Each round reviews your working tree, has the agent fix the open findings, runs the verify command it declared (sandboxed by default; `--no-sandbox` opts out), and gates the result. It stops on a pass, a round limit, a timeout (`--timeout`), a cost limit, or no progress, and it measures spend from the agent CLI's own output (`claude`, `opencode`, `codex`) instead of trusting the agent's self-report.
- **`verdict dashboard`.** A live, read-only terminal view of your reviews: a queue, per-review findings, risk-ordered diff lanes, a baseline compare, cost and precision. `--once` prints any tab as plain text.
- **Paste a PR link, or nothing at all.** Every verb that takes `<owner/repo> <pr>` also takes a pull or merge request URL, or works the target out from `origin` and your current branch; verbs that talk to the host ask it for the branch's PR when no local review names one. A target it cannot resolve exits 2 with the exact arguments to pass.
- **One gate you can trust.** `gate` is now the only gating verb, and it no longer passes a finding the cross-check never confirmed once the run's files are gone. `report` is the advisory read.
- **Safer around untrusted code and hosts.** Verdict's git calls never run hooks, fsmonitor, textconv or external diff drivers from the checkout under review. `gh` and `glab` calls for a PR URL or `origin` target are pinned to that host, so `GH_HOST` cannot send a review to another host's PR, and `post` always posts where its bundle came from. Self-hosted GitLab on a custom port works when `GITLAB_HOST` names it. Every `run --agent` and `loop` review now runs in a disposable copy of the reviewed tree, never in your checkout: an agent's writes land in the copy, only the review's own artifacts come back, and `claude` and `codex` are kept in their copy by their own tools. Secret files such as `.env` and private keys are never sent for review, and on macOS `verify --sandbox` warns when verdict's environment holds secret-named variables the sandboxed command could read.

### Breaking changes

verdict is pre-1.0, so these ship without compatibility shims. Each item says what to do.

- **`review.json` is findings-only.** `approved`, `body`, `comments[]` and `sections[]` are refused. Move each `comments[].body` to `findings[].claim`, add `quote`, `severity` and `confidence`, move `body` to `summary`, and drop `approved`.
- **A review must state its evidence.** With no gating finding it needs `receipts[]` for every changed hunk, and with no findings at all a non-empty `summary`. `verdict record --dry-run` names each gap.
- **`run --rounds` defaults to 2,** so an invalid review is re-prompted once. Pass `--rounds 1` for the old behavior.
- **`run --agent` runs two finders,** roughly doubling agent spend per run. Pass `--finders 1` or set `defaults.finders: 1` to keep one.
- **Finders launch without shell access** where the agent documents a flag for it (`claude`, `bob`, `pi`). Pass `--allow-shell` if your agent must run builds during review.
- **Every review agent runs in an OS sandbox** (`sandbox-exec` on macOS, `bwrap` on Linux): it writes only its snapshot and its own data (never its own settings, plugins or extensions), and cannot read `~/.ssh`, `~/.aws` or gh tokens. Without one (Windows, Linux without bubblewrap) `claude` and `codex` run warned and every other agent refuses `review-sandbox-unavailable`; install bubblewrap, or pass `--allow-unsandboxed-review` for a PR you trust.
- **Reviews run in a snapshot, never in your checkout.** Ignored folders such as `node_modules` are absent from what the reviewing agent reads, `claude` reviews load only your user-level Claude settings and no MCP server from the reviewed tree (`--setting-sources=user --strict-mcp-config`), and anything an agent writes besides its review artifacts is discarded with a warning. Keep review-relevant Claude settings in `~/.claude/settings.json`.
- **Panel receipts are version 2,** and version 1 is refused. Re-run `verdict panel`.
- **`gate` is the only gating verb.** `report --check`, `--completeness`, `--max-risk` and `--live` are gone: use `gate --max-severity`, `--require-head`, `--max-risk` and `--live`, and add `gate --coverage warn` while a review does not attest coverage.
- **`gate` fails on unconfirmed cross-checks** at the gated tier, even after the run's files are gone. Address those findings or complete the cross-check.
- **A prose-only spec owes one check,** the goal it states, and an `unmet` spec check withholds approval. Add the goal check to `spec_checks[]`.
- **Verify receipts bind content and are schema v2.** They carry `tree` instead of `head`, and v1 receipts are not read. Re-run `verdict verify` after upgrading.
- **`verify` runs in a snapshot, never in your checkout.** Ignored folders such as `node_modules` are absent, so install them in the command or list them in `verify.share`; `verify` outside a git checkout refuses.
- **A `VERIFIED` claim needs a verify receipt** for the graded content, and a `triage[]` claim of `addressed` refuses the review. Run `verdict verify` on the content you grade.
- **`verify --sandbox` is stricter.** On macOS, caches under `HOME` (npm, pip, cargo) can no longer be written, so point them at `$TMPDIR`; on Linux, a root whose `.git` cannot be pinned read-only refuses. Run `verify` from the top of a normal checkout.
- **`fix --test --commit` runs no git hooks.** Run your hooks yourself before you push.
- **Host mismatches refuse.** A `gh` or `glab` call that cannot be pinned to the target's host refuses `host-mismatch`. Re-fetch the target, or pass one on the bundle's host.
- **An unresolved target exits 2,** not 1, with the `target-unresolved` refusal. Update scripts that treated exit 1 as "no target".
- **One write switch for `mcp`, `serve` and `lsp`.** `mcp --operator` and `serve --interactive` are gone and local writes are on by default; `--read-only` removes them. Edit any `["mcp", "--operator"]` entry in your MCP config, then re-run `verdict mcp config --write`.
- **The installed skill is a small bootstrap skill.** Delete the old `verdict` skill directory and re-run `verdict skill install --agent <x>`, or `npx skills add stainless-code/verdict`.
- **Schemas moved** from `skills/verdict/schemas/` to `schemas/`, and every `$id` changed. Update your `$ref`s.
- **SDK cost token fields can be `null`,** meaning unknown, never a measured zero. Handle `null` in clients.
- **Behavioral-diagram knobs are removed:** `--diagram-behavioral`, `--diagram-expanded`, their `--no-` forms, settings keys and environment variables. Delete them.
- **The `degenerate-body` refusal is gone,** since verdict renders the body. Drop any handling for it.
- **Bundles from older verdict versions refuse `bundle-outdated`** instead of being read in a degraded mode: a `run.json` without its integrity binding, a `findings.json` whose `verification` is a bare array, a corpus bundle without `corpus_run.json`, and, for `config --preview`, a bundle directory without `run.json`. Re-fetch bundles and re-run reviews and benchmarks created before 0.8.0.
- **`ingest --sarif <file|->` is gone, and the source format is always named.** `--sarif` is an unknown flag now; the CLI, MCP and Go SDK all require the format. Use `ingest --from sarif <file|->`, pass `from: "sarif"` on an MCP `ingest` call, and set `From: verdict.SourceSARIF` on the SDK's `IngestRequest`.
- **`REVIEW_PUBLISH_ATTRIBUTION` takes `off`, `product` or `full`.** `true`/`false` are no longer accepted; use `product`/`off`.
- **A bad `--context` path refuses `context-invalid`,** not `fetch-failed`. Update scripts that match the code.
- **Secret files are always withheld** from review: `.env*` (templates excepted), private keys, credential files and Terraform state, with no override. Review them by hand.
- **`--consent-over-budget` covers one invocation.** Pass it on each run that needs it.
- **`fetch-local <word>` without `--` is a usage error.** Put path filters after `--`.
- **`docs/recipes/self-review.py` is removed.** Use `verdict loop`.

Every machine-readable answer from Verdict has the same shape: parse the envelope once, reuse it for every verb.

## The envelope

`verdict <verb> … --json` prints exactly one JSON object to stdout and nothing else; human progress goes to stderr. The nine top-level keys always appear in this order:

| Key              | Meaning                                                      |
| ---------------- | ------------------------------------------------------------ |
| `schema_version` | `"1"` today; refuse anything else                            |
| `verb`           | the verb that ran                                            |
| `repo`           | `owner/repo`, or `""` when the verb takes none               |
| `pr`             | the PR number, or `null` for repo-level verbs                |
| `at`             | UTC timestamp of the run, to the second                      |
| `next`           | the suggested follow-up command, or `""`                     |
| `warnings`       | non-fatal notices, also printed as `warn:` lines on stderr   |
| `data`           | the verb's result object, or `null` on failure               |
| `error`          | `null` on success, else `{code, message}` with a `try:` hint |

A failure keeps `data` null and names a typed `error.code` with its cause and fix in [Refusal codes](/docs/troubleshooting). A usage error (exit 2) prints no envelope at all: usage text goes to stderr.

## Exit codes

| Code | Meaning                                                                   |
| ---- | ------------------------------------------------------------------------- |
| `0`  | success; `error` is null                                                  |
| `1`  | typed refusal; read `error.code` and its `try:` hint, then fix and re-run |
| `2`  | usage error; check the flags (nothing on stdout)                          |
| `3`  | canceled run or tool failure                                              |

`report --check` and `gate` compose these for CI: `0` shippable, `1` a named dimension failed, `2` bad flags, `3` the gate itself broke. `run --agent` is the exception: when the agent exits non-zero, the process exit code is the agent's own, and `--json` disambiguates through `error.code`.

## Schemas

The shapes live in `skills/verdict/schemas/`, generated from `internal/schemagen/model.go` and shipped in the npm tarball. `envelope.schema.json` covers the envelope plus the pinned `report`, `post`, and `record` data shapes. Pin one by vendoring the file at a release tag and generating types from it — the Python client example checks in `models.py` generated exactly this way — and refuse at runtime when `schema_version` is not `"1"`.

## Worked example

```bash
verdict doctor --json
echo "exit: $?"
```

prints (abridged) with exit `0`:

```json
{
  "schema_version": "1",
  "verb": "doctor",
  "repo": "",
  "pr": null,
  "at": "2026-11-10T17:16:36Z",
  "next": "harness healthy",
  "warnings": [
    "token-scopes-excess: token grants more than runs need: gist, workflow — try: re-mint with only the repo scope (least privilege) and re-run"
  ],
  "data": {
    "healthy": true,
    "checks": [
      {
        "name": "gh-cli",
        "severity": "fail",
        "ok": true,
        "detail": "gh version 2.103.2 (2026-10-23)"
      }
    ]
  },
  "error": null
}
```

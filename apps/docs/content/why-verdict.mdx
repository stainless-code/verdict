AI review got good, then expensive, gated, and hard to trust. Every serious reviewer
converged on the same craft, then wrapped it in extraction. Verdict keeps the craft
and drops the extraction.

## The five pains

1. **Review latency.** Human review bottlenecks every team. PRs wait days for a look or
   merge unreviewed. Existing AI reviewers live in SaaS queues or post drive-by comments
   nobody trusts.
2. **Keys and data to strangers.** SaaS reviewers demand GitHub App installs, webhook
   access, and API keys in someone else's vault, metered on every run. Some bill every
   re-review as a brand-new review.
3. **Unverifiable AI output.** Most review bots post confident prose with no provenance:
   no evidence rung, no anchor checking, no record of what was claimed. Authors learn to
   ignore them, which is worse than no review at all.
4. **Anchor rot and re-report spam.** Comments anchored to moved lines, the same finding
   re-raised every push, threads resolved by fiat. Threads become noise, not a work list.
5. **Approval theater.** One-click approves on unexamined diffs, or blocking reviews with
   nothing behind them. The verdict carries no information about what was checked.

## How Verdict answers them

- **Latency becomes minutes, locally.** `fetch` pulls the bundle with no clone. Any agent
  you already run does the review. `post` lands exactly one native GitHub review. Total
  setup: `gh`, `jq`, one token.
- **Trust becomes nothing to exfiltrate.** There is no server side. Keys never leave your
  machine, diffs never leave your machine, and the roughly 900 lines of bash read in one
  sitting.
- **Output becomes verifiable.** Every finding carries an evidence rung from `said` to
  `reproduced`. Unproven claims ship labeled `unproven` or die. Anchors are
  machine-checked against the diff hunks, and suggestions render as real GitHub
  suggestion blocks or the post refuses to fake them.
- **Memory becomes stable.** Findings carry line-number-free signatures with status and
  append-only history. Re-reviews never re-report. Thread retirement is rule-bound.
- **Verdicts carry information.** A severity ladder maps to the author's actual next
  action, gated by machine rules: binding verdicts need `--bind`, approval is refused
  with open findings, self-verdicts downgrade. `calibrate` joins predictions against
  live ground truth, so accuracy is measured, not asserted.

## What it refuses to be

A CI gate that blocks merges. A daemon, watcher, or background loop. A model provider,
proxy, or router. A dashboard, database, or account system. A whole-repo mapper, a
worker fleet, an autonomous polish loop. A judge of anything it cannot anchor, verify,
or retract. Each refusal is load-bearing: they keep setup at minutes, blast radius at
one post, and the skill runnable on any model, anywhere.

## Where it concedes

SaaS reviewers keep the jobs that need servers: merge gating at enterprise scale,
fleet-wide policy, hosted audit trails. Everything else, the actual review, runs better
local: faster, cheaper, auditable, improvable by anyone who can read bash.

Verdict is a review loop you own. Fetch a review target — a host PR, a branch, a
commit range, staged changes — let your agent review it, grade the findings, post
exactly one review. Every surface below is built from the same verbs, and every
one of them runs on your machine: no account, no hosted state, no telemetry.

This page is the honest ledger. Shipped means the verb and its contract ship
today and are documented in the [manual](https://github.com/stainless-code/verdict/blob/main/docs/manual.md).
Planned means it is not built yet, and says so on its own line.

## Shipped today

| Stage         | Commands                                                                        | What they own                                                                                                                                                                                                                                                                           |
| ------------- | ------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Bundle        | `demo`, `fetch`, `fetch-local`, `index`                                         | One diff per review target, from a host PR or your working tree, into `.verdict/state/` (`demo` in a throwaway one), plus the local code index (`index build`) the impact answers read. Chunking and a budget gate are opt-in.                                                          |
| Review        | `run`, `loop`, `record`, `panel`, `ingest`, `adopt`, `fix`, `handoff`           | Launch your own agent on the bundle (`run`) or in self-review rounds (`loop`), merge its validated review into findings, plan disprove attempts (`panel`), ingest SARIF findings, carry local findings onto a PR, loop on one finding in scope, and hand the fix brief to someone else. |
| Decide        | `report`, `triage`, `threads`, `drain`, `risk`, `next`, `show`, `trend`, `gate` | Render the bundle, gate on severity (`--check`), compose the gate dimensions (`gate`), list review threads waiting on verdict, draft replies with your agent, and post them with `drain --post` (`drain`), queue the portfolio risk score (`risk`), and read trend across runs.         |
| Post          | `post`, `pr-wait`                                                               | Exactly one review, with anchor validation, stale-SHA and duplicate guards, `--dry-run`, and `--bind` for an approval, plus the computed topology and `Prompt for AI agent` blocks; `pr-wait` waits on a PR's checks, review, or merge state without writing anything.                  |
| Trust         | `verify`, `check-tree`, `doctor`, `calibrate`, `backtest`, `ready`, `journal`   | Check the bundle, the tree, the host login, past calibration, readiness, and the per-bundle invocation journal in one place, and mine, replay, and score bug-introducing candidates from your own history (`backtest`).                                                                 |
| Agent surface | `skill`, `mcp`, `acp`, `lsp`                                                    | The embedded skill (`skill`, `skill files`, `skill install`), the review verbs as MCP tools over stdio, read-only verdict queries as ACP v1 over stdio, and a review bundle's findings as editor diagnostics over LSP stdio.                                                            |
| Dashboard     | `serve`                                                                         | One read-only HTTP surface over `.verdict/state/`, with the browser inbox, review detail, threads, cost, precision, and gate panel; `report --html` exports the same views as static files.                                                                                             |
| Housekeeping  | `init`, `config`, `pack`, `learn`, `upgrade`, `uninstall`                       | Repo config, explain policy, lens packs (`pack list`, `pack test`, `pack add`), project rules with provenance, `init --ci github`, `--ci forgejo`, or `--ci gitlab` writing the every-PR workflow, and channel-aware upgrades and removals.                                             |

Clients and actions over those verbs: the Go SDK (`pkg/verdict`), the TypeScript
client (`@stainless-code/verdict/client`), the JSON schemas in `schemas/`, and
`setup-verdict` for GitHub Actions.

<Callout type="warning" title="Experimental until 1.0">
  The MCP server, the Go SDK, the TypeScript client and their schemas are
  experimental: they work, they are covered by tests, and their envelopes may
  still change before 1.0. Everything else in the table is stable.
</Callout>

## Next

**Incremental re-review on the remaining hosts.** `fetch --since` re-reviews
only new commits today on GitHub and GitLab. GitCafe, Forgejo, Bitbucket, and
Azure still get full fetches, and say so with an `incremental.diff.note` when
handed `--base-sha`. Planned for those hosts.

**Primitives before product.** New capability arrives as a verb with a schema, an
envelope and an exit code, so a script, an agent, an editor or the dashboard can
compose it. Nothing becomes a service you cannot run yourself.

## Never

A hosted control plane. A merge queue. Telemetry. Auto-merge. A model of our own.
Each of those would move the review — and the receipt — off your machine.

Order matters, so follow the steps.

<Callout type="info" title="Requirements">
  `gh` (authed), `git`, and a token with `repo` scope. Verdict brings everything
  else.
</Callout>

<Steps>
  <Step title="Install">
    <Tabs>
      <Tab title="Binary (verified)">
        ```bash
        curl -fsSL https://stainless-code.com/verdict/install.sh | sh
        ```
        macOS/Linux: installs `verdict` to `~/.verdict/bin` after verifying the
        checksum (and the cosign bundle when cosign is present). Pin with
        `VERDICT_VERSION=vX.Y.Z`, skip the
        PATH edit with `--no-modify-path`, and uninstall with
        `install.sh --uninstall --remove-path`. Windows:
        `irm https://stainless-code.com/verdict/install.ps1 | iex`.

        If the docs site is unreachable, or directly from GitHub Releases:
        `https://github.com/stainless-code/verdict/releases/latest/download/install.sh`
        (macOS/Linux) or
        `https://github.com/stainless-code/verdict/releases/latest/download/install.ps1`
        (Windows).
      </Tab>
      <Tab title="skills.sh">
        ```bash
        npx skills add stainless-code/verdict
        ```
      </Tab>
      <Tab title="Clone">
        ```bash
        git clone https://github.com/stainless-code/verdict.git
        cd verdict && make build && ./install-skill.sh
        ```
        `install-skill.sh` runs `doctor` first and symlinks the skill into your
        agent's skills directory. `git pull` is the updater. (This script was
        called `install.sh` before 0.4; that name is now the binary installer.)
      </Tab>
    </Tabs>

  </Step>
  <Step title="Scaffold local defaults (optional)">
    ```bash
    verdict init --preset standard
    ```
    Writes starter `.review/` control files (budget, panel, KB policy and rules)
    then runs check-tree validation. Pure-local and skippable: fetch works
    without it.
  </Step>
  <Step title="Fetch the bundle">
    ```bash
    verdict fetch owner/repo 123
    ```
    One command pulls the diff, metadata, threads, and file roles into `.review/123/`.
    No clone needed. Done when the directory holds `PR.json`, `full.diff`, `toc.txt`,
    and `roles.txt`.
  </Step>
  <Step title="Review with any agent">
    The skill you installed in step 1 is the prompt: the agent discovers
    `SKILL.md` in its skills directory and loads the mode file it names. A global
    binary install can add it with `verdict skill install --agent <name>`. Point
    the agent at `.review/123/` (the bundle from step 2); it reads the whole diff
    first, fans out read-only lens subagents with one falsifiable question each,
    and writes exactly one `.review/123/review.json`.
  </Step>
  <Step title="Post">
    ```bash
    verdict post owner/repo 123 --approve=false
    ```
    Anchors are machine-checked against the diff hunks, suggestions go in as real
    GitHub suggestion blocks, and exactly one review lands. Done when one review
    exists: one `review.json`, one post call.
  </Step>
  <Step title="Read the report">
    ```bash
    verdict report owner/repo 123
    ```
    One offline read of the store: ranked open findings, the verdict, and counts.
    `verdict next` names the top actionable finding and the command to act on it;
    `report --json` is the same data for a script. Done when you have a ranked
    list you can act on.
  </Step>
  <Step title="Re-review new commits">
    ```bash
    verdict fetch owner/repo 123 --base-sha <prior-reviewed-sha>
    ```
    Then review with `prompts/incremental-review.md` instead of `prompts/review.md`.
    Recorded findings are never re-reported. Threads retire by rule.
  </Step>
  <Step title="No PR? Review the worktree">
    ```bash
    verdict fetch-local owner/repo work
    verdict record owner/repo local-work
    ```
    Same review, no GitHub object: bundle the worktree (`--staged`, `--range`,
    `--base`, and `--stash` variants exist), review it the same way, and `record`
    merges the findings store instead of posting. `adopt` carries the findings
    into a PR fetch later.
  </Step>
</Steps>

## What you got

A grounded first pass on the PR in minutes, with every claim carrying an evidence
rung and every comment anchored to a real hunk. Humans spend their attention on the
hard parts.

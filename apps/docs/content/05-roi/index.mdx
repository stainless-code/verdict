Verdict is MIT licensed with no seats, no subscription, and no per-review charge.
This page publishes the measured safety numbers from the shipped review flow,
tracks recall honestly with its `N` and fixtures, and gives you an offline
calculator that compares seat-priced hosted reviewers against your own
`report --cost` spend.

## Measured safety (headline)

Scored with the product scorer (`verdict backtest fixtures`) over the shipped
review flow (arm `C2`: default `verdict run` with 2 rounds, `record`, and
`report --check important --max-risk medium`) in the checked-in snapshot
[`bench/quality/results/2026-11-20/`](https://github.com/stainless-code/verdict/tree/main/bench/quality/results/2026-11-20):

- **0 / 16 false greens** (`0/8` on `fx1`, `0/8` on `fx2`, `0` unknown gate
  outcomes) — no approval or passing gate without verified evidence.
- **0 / 46 hallucinated quotes** (`0.0000` measured rate across `36` gating
  findings on `fx1` and `10` on `fx2`, `0` unverifiable) — every gating finding
  quote verified against the pinned diff.
- **0 `review-insufficient` refusals** and **8 / 8 calibration rows
  reproduced**.

Every number on this page is re-derivable offline from the repository:

```bash
verdict backtest fixtures --recordings bench/quality/results/2026-11-20
```

**Scope of the snapshot (2026-11-20):** recordings collected `2026-11-19` on
commit `9d7fc865f` over two known-defect fixtures (`fx1` and `fx2`) and two
drivers — `pi-opencode-go-hy4-flash-free` (`hy4-flash`, `N=5` per fixture) and
`pi-deepseek-deepseek-flash` (`DeepSeek V4.1 Flash`, `N=3` per fixture), for
`N=8` scored runs per fixture (`16` runs total). Rates describe recorded
reviews on these two fixtures, not a universal model claim.

## Cost calculator: seats vs. bring-your-own model

Hosted reviewers typically bill per developer seat or per metered review — see
the [comparison page](/compare) for published vendor rates (checked
`2026-11-04`). With Verdict, the binary and skill carry no seat fee; your only
variable cost is the model provider's token spend (or `$0` with a local model).

Every default value in the calculator below is an **estimate**. Replace the
model spend per PR with your own `verdict report <repo> <pr> --cost` output to
project from your actual runs.

## Reading real spend from `report --cost`

Verdict sums each bundle's `.verdict/state/<pr>/cost.json` (and per-chunk
records) when you run `report --cost`:

```bash
verdict report owner/repo 123 --cost
verdict report owner/repo 123 --cost --json
```

The human output prints one summary line plus effort-tier run counts:

```text
cost: 1 run(s), 1 with records — in=42000 out=3500 total=45500 est_usd=0.18 cached=0
tiers: cheap=0 standard=1 deep=0
```

Under `--json`, `data.cost` carries `runs`, `runs_with_cost`, `input_tokens`,
`output_tokens`, `total_tokens`, `cached_input_tokens`, `est_usd`, and
`by_tier.{cheap,standard,deep}` (plus `receipts` when `--consent-over-budget`
was used). Verdict sums what the agent recorded and never prices tokens itself:
an absent or `null` `est_usd` stays unknown rather than zero. To price the
pre-run budget gate (`REVIEW_BUDGET_USD`) from measured harness transcripts
instead of self-reported `est_usd`, pass `VERDICT_USAGE` as documented in the
[manual's cost control section](https://github.com/stainless-code/verdict/blob/main/docs/manual.md#cost-control-budget-estimate-consent).
